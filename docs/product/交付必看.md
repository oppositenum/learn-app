# 交付必看

本文件按 `docs/product/互动式学习_V1.md`（V1.2，唯一现行基准）拆分交付模块。旧交付步骤全部作废，不再引用。

- 模块只从需求文档拆出，不从旧清单、聊天记录或现有页面反推。
- 标注「在现有能力上交付」的模块，不推倒现有课堂，只把需求里的这一件事做到可验收。
- 「在现有能力上交付：是」和「已实现」只说明代码里有入口，不等于验收通过。M02、M03、M08、M12 等标了现有能力的模块，轮到时仍要按各自的验收项逐项证明，不能跳过。是否通过，以本文件的验收和 `docs/quality/v1-acceptance.md` 为准。
- 所有模块都受 `AGENTS.md` 14 条约束。孩子端任何页面和网络响应都不得出现标准答案；320px 必须可用；动画必须支持 `prefers-reduced-motion`。

---

## 界面与交互

本节只定界面规则，不重写模块，不新增模块，各模块正文不因本节改动。

### 范围

- 这是 V1，只给一个初三孩子用。
- 界面按中国学生习惯的手机用法做：底部导航、一屏一件事、大字、大按钮。
- 不按教辅 App、排行榜或游戏商城的样子设计。
- 商用以后再谈，本版不加任何商用界面。

### 页面

- 学生端页面：首页、课堂、语音讲解、知识补给、成长、我的。
- 学生端底部导航只有：首页、成长、我的。
- 家长端只有现有页面：首页、实时、报告、能力、设置。
- 不新增页面。追问不做成单独的对话窗口；休息不做成单独的呼吸页。

### 每道题的固定顺序

1. 作答
2. 检查思路
3. 拆小一步
4. 换生活例子
5. 讲解
6. 回到原题自己做

- 命中情绪信号时，这一轮先休息，仍停在原题上。休息不是新页面。
- 「我不会」是求助，不是休息。
- 答对后不自动跳题。

### 屏幕内容

- 课堂屏只放四块：题目、老师这一轮的话、作答、提交。
- 语音屏只放：正在读的句子、播放或暂停、再听一句、我懂了回原题。
- 暂停说明和失败提示只在发生时插入。
- 没有音频时，可以显示完整的文字讲解。

### 各端通用规则

- 孩子阅读的文字不小于 16px；当前句可以更大。
- 主按钮高度不小于 48px。
- 320px 宽度下不出现横向滚动。
- 按下缩放持续 150ms–400ms；`prefers-reduced-motion` 下不播放。
- 学生端不出现：标准答案、完整解析、错误、红叉、分数、排名、经验值、徽章、和同龄人比较。
- 答错时给老师的下一句引导。休息用平静样式，引导用暖色，前进用绿色。
- 家长可以在家长页面看到答案；孩子页面和孩子端接口不得出现答案。家长不能把答案发给孩子。

### 后续模块

凡改动界面的后续模块，先对照本节；不符合就停下，不在模块里另做一套界面。

## 三、每个模块的做法

1. 一个模块一份令文。令文写明模块编号、怎样算做完、怎样验收，以及基于哪个 40 位 SHA。
2. 一个模块一个 commit。只提交令文列出的路径，不 push。只有发布令文才能 push 和部署。
3. 提交前跑 `AGENTS.md` 规定的全部门禁：go vet、go test、真实 PostgreSQL 集成测试、npm test、npm run lint、npm run build。回报贴原始输出。
4. 一次发布只上一个模块。发布后按该模块「怎样验收」逐项检查：
   - 页面检查由终端 Codex 在测试机执行；账号由 Owner 亲手登录，令文里不写凭据。
   - 只报元素和数值，不报题目、答案或老师原话。
   - 写入学习记录的操作压到最少。
   - 最后由 Owner 真机验收。
5. 验收不通过，就停在该模块修到通过。不跳到下一个模块，也不并行开下一个模块。
