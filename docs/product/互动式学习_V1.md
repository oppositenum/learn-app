# 互动式学习 V1
## AI Learning Tutor — 全学科苏格拉底式互动学习平台原型与工程规格

**版本：** V1.1
**生效日期：** 2026-09-05
**状态：** Current Product and Acceptance Baseline / 现行开发与验收基准
**目标终端：** 手机 Web、平板 Web、PC Web；后续同一后端接微信小程序  
**第一阶段核心学科：** 数学、语文、英语、物理、化学

# 0. 产品一句话定义

AI Learning Tutor 不是“视频课 + 刷题”的电子化版本，而是一个持续理解孩子当前能力、通过苏格拉底式追问让孩子自己形成答案、将课本知识连接到生活、人文、科学和真实世界，并根据学习表现实时调整计划的 AI 私人导师。

系统必须做到：

> 孩子负责思考，AI 负责启发，程序负责教学纪律，家长负责监督和方向。

# 1. V1 不可改变的产品原则

## 1.1 五科骨架从第一天统一设计

第一版数据库、API、Tutor Engine、Planner Engine、前端路由不得写死为 Math-only。

固定学科：

```text
MATH
CHINESE
ENGLISH
PHYSICS
CHEMISTRY
```

未来允许无侵入扩展：

```text
BIOLOGY
GEOGRAPHY
HISTORY
CIVICS
```

## 1.2 孩子端不得获得标准答案

这不是 UI 隐藏，而是服务端权限边界。

Student API 不得返回：

- `correct_answer`
- `full_solution`
- `teacher_reference_answer`
- `scoring_key`
- `answer_explanation`
- 私有 misconception mapping
- 下一步可直接推导标准答案的隐藏字段

即使孩子打开浏览器 DevTools，也不能从网络响应或前端状态读取标准答案。

## 1.3 AI 不能直接控制掌握状态

AI 可以提供结构化判断：

```text
answer_correct
reasoning_quality
misconception
emotion_signal
recommended_action
```

但 AI 不得直接执行：

```text
mastery = true
difficulty++
skip_prerequisite = true
```

最终状态由服务端规则引擎决定。

## 1.4 AI 不以“告诉答案”为默认教学方式

默认教学顺序：

```text
ASK
→ PROBE
→ HINT
→ SCAFFOLD
→ ANALOGY
→ BACKTRACK
→ EXPLAIN_WITH_PARALLEL_EXAMPLE
→ RETURN_TO_ORIGINAL
→ VERIFY
```

只有 Tutor Engine 明确授权：

```text
answer_reveal_allowed = true
```

教学 Agent 才允许展示原题答案。

V1 正常课堂默认：

```text
answer_reveal_allowed = false
```

### V1.1 分级引导材料纪律

- `[REQ-TEACH-01]` `PROBE`、`HINT`、`SCAFFOLD`、`ANALOGY` 必须保留原题数字与知识结构，不得通过随意换数字增加额外认知负担。**实现状态：已实现（B3）。**
- `[REQ-TEACH-02]` 仅 `EXPLAIN` 允许使用同构但不同数字的完整示范；示范仍不得把原题答案作为默认输出。**实现状态：已实现（B3）。**
- `[REQ-TEACH-03]` `EXPLAIN` 完成后必须立即返回原题验证，不得以平行例题完成代替原任务。**实现状态：已实现（B3）。**

## 1.5 “生活化”不是给课本题换皮

生活世界必须承担真实理解功能。

例如“一次函数”不是把 `y=2x+10` 改成“奶茶故事”就结束，而要经历：

```text
真实费用变化
→ 表格观察
→ 每增加1单位发生什么
→ 固定起点是什么
→ 图像/坐标
→ y=kx+b
→ 回到课本题
```

V1.1 取代标注：上面的生活化路径仍完整保留；在分级引导中，场景变化不得改变原题数字与知识结构，具体遵守 `[REQ-TEACH-01]` 至 `[REQ-TEACH-03]`。只有进入 `EXPLAIN` 才允许用同构不同数字完成示范，随后立即回到原题。

## 1.6 错误是诊断信号，不是惩罚对象

不因为答错：

- 扣积分；
- 红色大叉震屏；
- 给负面排名；
- 强制重新刷 10 道相同题。

奖励重点放在：

- 主动思考；
- 自我纠错；
- 提示后理解；
- 多日后复习成功；
- 真正掌握；
- 坚持完成学习。

# 2. 三端产品结构

系统有三个独立角色前端，共享同一个 Go 后端。

```text
                    ┌────────────────────┐
                    │ AI Learning Server │
                    └─────────┬──────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
        ▼                     ▼                     ▼
 Student Web              Parent Web            Owner/Admin
 孩子手机/PC              家长手机/PC            内容与运营
        │                     │                     │
        └─────────────────────┼─────────────────────┘
                              │
                        Server Authority
```

## 2.1 Student Web

目标：

- 一屏一任务；
- 能文字回答；
- 能语音回答；
- 能点“提示”；
- 能点“我不会”；
- 不暴露标准答案；
- 不展示让孩子产生失败感的百分比；
- 自动适配手机/平板/PC。

## 2.2 Parent Web

目标：

- 实时知道孩子是否正在学习；
- 当前学科/知识点；
- 当前是独立思考、提示、回退还是语音讲解；
- 能查看标准答案和教师层解释；
- 看知识薄弱点、能力变化、复习结果；
- 能设置今日重点/学习时长/现实奖励；
- 能降低当天强度；
- 不能直接把答案发送到孩子端。

## 2.3 Owner/Admin

目标：

- 内容发布；
- 题库审核；
- AI 调用与成本；
- 教学异常；
- 模型路由；
- 数据质量；
- 课程版本；
- Codex 内容流水线；
- 审核日志。

## 苏格拉底式语文原则

不要问完后直接给“标准答案”。

例如阅读题：

```text
Q1 文中发生了什么？
Q2 哪一句最能支持你的判断？
Q3 如果删掉这句话，你的结论还成立吗？
Q4 作者为什么没有直接说“他很难过”？
Q5 用你自己的话重新概括。
```

核心训练：

```text
观点必须有文本证据。
```

- 同一事件不同人物如何叙述；

# 11. 难度体系

所有科目统一使用 L0-L5，但每科含义可具体化。

```text
L0 = 生活直觉 / 观察
L1 = 单步骤 / 直接识别
L2 = 两步骤 / 基础迁移
L3 = 学校标准基础题
L4 = 变式 / 信息隐藏 / 方法选择
L5 = 综合 / 跨知识点
```

基础薄弱孩子默认活动区：

```text
L0-L3
```

不是按照“初二学生”硬塞 L3/L4。

### V1.1 年级硬边界

- `[REQ-GRADE-01]` 所有 Planner、直接取题和课堂路径都必须满足 `grade_bands.min_grade <= students.grade_level`，任何模式均不得向上超前；`CURRENT_GRADE` 还必须满足 `students.grade_level <= grade_bands.max_grade`，仅 `REMEDIATION`、`MICRO_BACKTRACK`、`REVIEW` 可向下跨学段。启用学科缺少候选时，fallback 可以放宽学科，但绝不允许放宽年级上界。**实现状态：已实现（B1A）。**

当前课程元数据只有 `PRIMARY`（1–6）和 `JUNIOR_SECONDARY`（7–9）两个粗粒度学段，因此本要求实现的是学段边界而非精确到单一年级的过滤；精确年级过滤需要后续为知识点补充适用年级元数据。

## 12.3 V1.1 教学动作约束

## 12.4 已实现的会话生命周期与计时

- `[REQ-SESSION-01]` 会话生命周期为 `ACTIVE`、`PAUSED`、`COMPLETED`、`ABANDONED`；结束态不得再次恢复。**实现状态：已实现（P0）。**
- `[REQ-SESSION-02]` 学习时长以服务端为权威，只累计真实活跃区间；生产路径禁止使用 `now - started_at` 作为学习时长。过期回收必须以最后一次有效心跳的 `last_activity_at` 作为计时检查点，不得把 90 秒阈值及扫描等待计入学习时长。**实现状态：已实现（P0/B2.1）。**
- `[REQ-SESSION-03]` 客户端只在最后一次真实交互仍处于短于服务端 90 秒阈值的新鲜窗口时发送课堂心跳；真实交互至少包括键盘输入、指针操作、滚动及语音录制开始与结束。学生停止操作后心跳自然停止，服务端在过期阈值与扫描周期内将会话置为 `PAUSED`；暂停满 24 小时自动放弃。`visibilitychange` 与 `pagehide` 可作为即时暂停的快速路径，但学习时长正确性不得依赖浏览器焦点 API。**实现状态：已实现（P0/B2.1）。**
- `[REQ-SESSION-04]` 每个学生同时最多存在一个未结束会话，由数据库唯一约束保证。**实现状态：已实现（P0）。**
- `[REQ-SESSION-05]` 登出或替换当前身份时，服务端必须在同一事务内撤销当前认证会话并将该用户的 `ACTIVE` 学习会话按权威计时检查点收口为 `PAUSED`，持久化并发布与手动暂停相同的实时事件；已通过中间件的旧请求也必须在生命周期写事务内重新确认认证会话未被撤销，保证身份切换后最终状态不为 `ACTIVE`。客户端必须在新身份登录前成功登出旧身份，并通过既有跨标签广播停止旧身份的课堂写入。**实现状态：已实现（B1B）。**

## 12.5 V1.1 课堂原子闭环

- `[REQ-CLASSROOM-01]` 同一课堂必须真实经过 `VARIANT → ABSTRACT → VERIFY → COMPLETE`，不得把中间阶段伪装成瞬时状态或在首次正确后直接完成。**实现状态：机制已验证；产品激活未验证（仅完整 `READY` 任务谱系启用，不完整谱系 fail closed）。**
- `[REQ-EVIDENCE-01]` 证据形式必须由学生实际完成的课堂阶段决定，不得由计划 `mode` 机械决定。**实现状态：机制已验证；产品激活未验证（B4）。**

# 13. Socratic Patience Limits 苏格拉底熔断

这是 V1 的硬规则。

## 13.1 默认追问上限

同一认知瓶颈：

```text
max_socratic_failed_rounds = 3
```

不是同一道题机械问 3 次，而是 3 次有效启发尝试。

示例：

```text
Round 1: 检查当前思路
Round 2: 拆小一步
Round 3: 换生活类比
```

仍失败：

```text
必须熔断。
```

进入：

```text
EXPLAIN_WITH_PARALLEL_EXAMPLE
```

或者：

```text
VOICE_EXPLAIN
```

V1.1 取代标注：前三次有效启发必须保留原题数字与知识结构（`[REQ-TEACH-01]`）；熔断后的完整示范仅可在 `EXPLAIN` 使用同构不同数字（`[REQ-TEACH-02]`），并须立即返回原题验证（`[REQ-TEACH-03]`）。

熔断示范后返回原题的独立验证若仍未通过，当前课堂必须以 `SOCRATIC_REPROOF_FAILED` 安全结束，不得再次调用模型重复示范，也不得写入成功证据、奖励或复习成败。**实现状态：机制已验证；产品激活未验证（B4）。**

## 13.2 情绪优先熔断

若检测到以下信号：

```text
“烦死了”
“不想做”
“随便”
“你直接告诉我吧”
“我不知道不知道”
连续随机回答
长时间无输入
明显重复敷衍
```

AI Analyzer 输出：

```json
{
  "emotion_signal": "FRUSTRATED",
  "engagement": "LOW",
  "recommended_action": "DEESCALATE"
}
```

Tutor Engine 可执行：

```text
1. 停止继续追问原逻辑
2. 改成更简单生活场景
3. 允许语音讲解
4. 允许短休息
5. 必要时结束当前知识点
```

## 13.3 不允许的行为

- 连续 7、8 轮追问同一问题；
- “再想想”反复循环；
- 因孩子答不上而讽刺；
- 讲一大段后立即上高难题；
- 用奖励强迫继续。

# 15. Mastery 掌握状态

```text
UNKNOWN
EXPOSED
LEARNING
ASSISTED
UNDERSTOOD
MASTERED
REVIEW_DUE
REGRESSED
```

## UNDERSTOOD

至少满足：

- 不同表达形式；
- 非完全重复题；
- 至少一次独立完成。

## MASTERED

建议至少满足：

```text
生活情境独立完成
+
变式独立完成
+
课本形式验证
+
间隔复习成功
```

一次答对绝不能变成 MASTERED。

## V1.1 严格掌握语义

- `[REQ-MASTERY-01]` `ASSISTED` 表示学生在认知提示或教学支架后完成，已经跟上当前步骤，但尚无独立证据。**实现状态：已实现（P0）。**
- `[REQ-MASTERY-02]` `UNDERSTOOD` 要求学生后续至少一次在无认知帮助下独立完成，并具备多种表达形式的证据。**实现状态：已实现（P0）。**
- `[REQ-MASTERY-03]` `MASTERED` 要求生活情境、变式、课本验证、跨时间复习四类证据完整。**实现状态：已实现（P0）。**
- `[REQ-MASTERY-04]` 受助成功不得填充上述四类独立证据计数器，也不得直接获得 `MASTERY` 奖励。**实现状态：已实现（P0）。**
- `[REQ-MASTERY-05]` 受助后，系统必须提供新的、非重复任务，让学生重新独立证明；不得降低“独立”的定义。**实现状态：机制已验证；产品激活未验证（B4）。**
- `[REQ-ASSIST-01]` 已实现的认知帮助等级为：`PROBE=1`、`HINT=1`、`SCAFFOLD=2`、`ANALOGY=3`、`BACKTRACK=3`、`EXPLAIN=4`、`VOICE_EXPLAIN=4`。**实现状态：已实现（P0）。**
- `[REQ-ASSIST-02]` `BREAK=0`；`BREAK` 是情绪降级状态，不是学业或认知帮助。**实现状态：已实现。**

成长指标必须从上述真实证据派生：

- `[REQ-GROWTH-01]` `total_energy` 仅作为兼容字段保留，不再作为成长页主指标。**实现状态：已实现（B6）。**
- `[REQ-GROWTH-02]` 成长页主指标为独立解决、帮助后理解、自我纠正、迁移成功、延迟复习；每项必须能解释到对应学习事件或证据来源。**实现状态：已实现（B6）。**

五类成长指标使用 `growth-evidence-v1` 投影。独立解决和迁移成功只计入确定性授权的掌握证据；帮助后理解来自确定性成功的受助证据；自我纠正要求同一课堂任务或阶段先有确定性失败、后有确定性成功；延迟复习来自独立成功关闭的复习队列项。响应只返回来源类型、来源 ID、学科、知识点、阶段或证据形式及发生时间，不返回作答或 Tutor 正文。每类返回总数及最近 20 条来源，超过时明确标记截断。

课堂证据仍须遵守 `[REQ-CLASSROOM-01]` 与 `[REQ-EVIDENCE-01]`，不能用计划模式替代真实阶段。

## 19.1 STT 语音回答

孩子可按住或点击麦克风：

```text

→ 上传服务端
→ STT
→ 显示识别文字
→ 孩子确认/提交
```

低年级和不愿打字时特别有价值。

## 19.2 TTS 讲解

触发：

```text
VOICE_EXPLAIN
```

场景：

- Socratic 三轮失败；
- 孩子主动点“给我讲讲”；
- 情绪降级；
- 需要语言/英语发音训练。

## 19.3 语音与文字同步

讲解响应包含语义片段：

```json
{
  "segments": [
    {
      "id": "seg_1",
      "text": "先看总价36元。",
      "audio_timing": {
        "start_ms": 0,
        "end_ms": 1820
      }
    }
  ]
}
```

前端播放时：

- 当前句高亮；
- 可暂停；
- 可重播当前句；
- 可切回文字；
- 不强制自动播放。

## 19.4 V1 动画原则

语音讲解时只做：

- 重点数字高亮；
- 箭头；
- 逐步出现；
- 当前文本行高亮。

不做复杂人物口型或 3D 老师。

## 37.1 V1.1 学习效果与异常指标

- `[REQ-METRICS-01]` 必须定义并采集：首次回答有效时长、学生交互占比、无提示及各提示层级完成率、迁移正确率、D+1/D+7 复习保持率、“我不会”后重新参与率、退出阶段、AI 异常率。**实现状态：已实现（B6）。**
- `[REQ-METRICS-02]` 分析表不得保存学生答案正文或原始音频；指标只保存计算所需的最小事件、分类和时间信息。**实现状态：已实现（B6）。**

`learning-effect-event-v1` 以追加式最小事件计算上述学习效果。学生交互占比明确是“作答与主动求助事件数 /（作答、主动求助与 Tutor 输出事件数）”，不是说话时长。首次回答有效时长分别返回课堂总样本数、可测样本数和平均值，无法重建的历史值保持 `NULL` 且不按零计入。AI 异常率当前定义为结构化 AI 请求中非 `SUCCEEDED` 分类的占比；分类只保存 provider、model、purpose、有限结果枚举、可选 HTTP 状态和时延，不保存 provider 响应或错误正文。

B6 成本计量待办：测试环境第三方网关的审核请求实测约含 4390 个输入 token（其中 3840 个缓存 token），单次样本审核成本约为 Tutor 生成成本的 4.8 倍；该比例只代表本次样本，不得外推为固定单位成本。当前 `ai_price_catalog` 没有 cache-write 价格字段，GPT-5.6+ 的缓存写入成本可能被低估，因此现有成本统计不得宣称完全精确；Terra 的 $2.50/1M cache-write 参考价格后续必须使用专用字段核算，不得借用任何音频价格字段。

# 45. OpenAI/Codex 当前能力约束

截至本规格编写时，OpenAI 已公开 Codex SDK，可将 Codex agent 嵌入应用/工作流，并提供结构化输出与上下文会话能力。因此在工程上可以实现 `TeachingAgentGateway -> CodexProvider`。

但产品层必须保持：

```text
Codex Developer
!=
Codex Tutor
```

孩子学习使用的 Tutor 必须运行在受限教学工具集之上。

语音层必须通过 provider adapter 封装，避免前端/业务逻辑绑定单一模型。

AI API 定价会变化，因此 `estimated_cost` 计算不能硬编码到业务代码；应使用版本化 price table：

```text
ai_price_catalog
provider
model
effective_from
input_price
cached_input_price
output_price
audio_price
```

每次调用记录所采用的 price catalog version。

# 46. 最终产品原则

V1 所有设计决策可以用以下问题检查：

> 这个功能是在帮助孩子自己形成理解，还是只是更快地把答案告诉孩子？

如果答案是后者，默认不做。

最终体验必须形成：

```text
世界提出问题
        ↓
孩子产生好奇
        ↓
AI不断追问
        ↓
孩子开始推理
        ↓
遇到困难
        ↓
系统识别根因
        ↓
换场景 / 补基础 / 语音讲解
        ↓
孩子自己重新解决
        ↓
抽象成课本知识
        ↓
隔几天重新验证
        ↓
孩子发现：
“原来这个知识真的能解释世界。”
```

这就是 AI Learning Tutor 与传统“老师讲、学生听、然后刷题”的根本区别。
