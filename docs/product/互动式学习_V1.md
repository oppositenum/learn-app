# 互动式学习 V1
## AI Learning Tutor — 全学科苏格拉底式互动学习平台原型与工程规格

**版本：** V1.0  
**状态：** Product Baseline / 可直接进入 Codex 建仓开发  
**目标终端：** 手机 Web、平板 Web、PC Web；后续同一后端接微信小程序  
**第一阶段核心学科：** 数学、语文、英语、物理、化学  
**覆盖学段：** 小学 + 初中（课程骨架全覆盖，内容可分批装载）  
**核心教学原则：** 生活/世界问题先行 → 苏格拉底追问 → 知识抽象 → 课本验证 → 反复复习 → 家长同步监督

---

# 0. 产品一句话定义

AI Learning Tutor 不是“视频课 + 刷题”的电子化版本，而是一个持续理解孩子当前能力、通过苏格拉底式追问让孩子自己形成答案、将课本知识连接到生活、人文、科学和真实世界，并根据学习表现实时调整计划的 AI 私人导师。

系统必须做到：

> 孩子负责思考，AI 负责启发，程序负责教学纪律，家长负责监督和方向。

# 1. V1 不可改变的产品原则

## 1.1 五科骨架从第一天统一设计

第一版数据库、API、Tutor Engine、Planner Engine、前端路由不得写死为 Math-only。

固定学科：

```text
MATH
CHINESE
ENGLISH
PHYSICS
CHEMISTRY
```

未来允许无侵入扩展：

```text
BIOLOGY
GEOGRAPHY
HISTORY
CIVICS
```

## 1.2 孩子端不得获得标准答案

这不是 UI 隐藏，而是服务端权限边界。

Student API 不得返回：

- `correct_answer`
- `full_solution`
- `teacher_reference_answer`
- `scoring_key`
- `answer_explanation`
- 私有 misconception mapping
- 下一步可直接推导标准答案的隐藏字段

即使孩子打开浏览器 DevTools，也不能从网络响应或前端状态读取标准答案。

## 1.3 AI 不能直接控制掌握状态

AI 可以提供结构化判断：

```text
answer_correct
reasoning_quality
misconception
emotion_signal
recommended_action
```

但 AI 不得直接执行：

```text
mastery = true
difficulty++
skip_prerequisite = true
```

最终状态由服务端规则引擎决定。

## 1.4 AI 不以“告诉答案”为默认教学方式

默认教学顺序：

```text
ASK
→ PROBE
→ HINT
→ SCAFFOLD
→ ANALOGY
→ BACKTRACK
→ EXPLAIN_WITH_PARALLEL_EXAMPLE
→ RETURN_TO_ORIGINAL
→ VERIFY
```

只有 Tutor Engine 明确授权：

```text
answer_reveal_allowed = true
```

教学 Agent 才允许展示原题答案。

V1 正常课堂默认：

```text
answer_reveal_allowed = false
```

## 1.5 “生活化”不是给课本题换皮

生活世界必须承担真实理解功能。

例如“一次函数”不是把 `y=2x+10` 改成“奶茶故事”就结束，而要经历：

```text
真实费用变化
→ 表格观察
→ 每增加1单位发生什么
→ 固定起点是什么
→ 图像/坐标
→ y=kx+b
→ 回到课本题
```

## 1.6 错误是诊断信号，不是惩罚对象

不因为答错：

- 扣积分；
- 红色大叉震屏；
- 给负面排名；
- 强制重新刷 10 道相同题。

奖励重点放在：

- 主动思考；
- 自我纠错；
- 提示后理解；
- 多日后复习成功；
- 真正掌握；
- 坚持完成学习。

# 2. 三端产品结构

系统有三个独立角色前端，共享同一个 Go 后端。

```text
                    ┌────────────────────┐
                    │ AI Learning Server │
                    └─────────┬──────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
        ▼                     ▼                     ▼
 Student Web              Parent Web            Owner/Admin
 孩子手机/PC              家长手机/PC            内容与运营
        │                     │                     │
        └─────────────────────┼─────────────────────┘
                              │
                        Server Authority
```

## 2.1 Student Web

目标：

- 一屏一任务；
- 能文字回答；
- 能语音回答；
- 能点“提示”；
- 能点“我不会”；
- 不暴露标准答案；
- 不展示让孩子产生失败感的百分比；
- 自动适配手机/平板/PC。

## 2.2 Parent Web

目标：

- 实时知道孩子是否正在学习；
- 当前学科/知识点；
- 当前是独立思考、提示、回退还是语音讲解；
- 能查看标准答案和教师层解释；
- 看知识薄弱点、能力变化、复习结果；
- 能设置今日重点/学习时长/现实奖励；
- 能降低当天强度；
- 不能直接把答案发送到孩子端。

## 2.3 Owner/Admin

目标：

- 内容发布；
- 题库审核；
- AI 调用与成本；
- 教学异常；
- 模型路由；
- 数据质量；
- 课程版本；
- Codex 内容流水线；
- 审核日志。

## 苏格拉底式语文原则

不要问完后直接给“标准答案”。


```text
观点必须有文本证据。
```

# 11. 难度体系

所有科目统一使用 L0-L5，但每科含义可具体化。

```text
L0 = 生活直觉 / 观察
L1 = 单步骤 / 直接识别
L2 = 两步骤 / 基础迁移
L3 = 学校标准基础题
L4 = 变式 / 信息隐藏 / 方法选择
L5 = 综合 / 跨知识点
```

基础薄弱孩子默认活动区：

```text
L0-L3
```

不是按照“初二学生”硬塞 L3/L4。

# 13. Socratic Patience Limits 苏格拉底熔断

这是 V1 的硬规则。

## 13.1 默认追问上限

同一认知瓶颈：

```text
max_socratic_failed_rounds = 3
```

不是同一道题机械问 3 次，而是 3 次有效启发尝试。

示例：

```text
Round 1: 检查当前思路
Round 2: 拆小一步
Round 3: 换生活类比
```

仍失败：

```text
必须熔断。
```

进入：

```text
EXPLAIN_WITH_PARALLEL_EXAMPLE
```

或者：

```text
VOICE_EXPLAIN
```

## 13.2 情绪优先熔断

若检测到以下信号：

```text
“烦死了”
“不想做”
“随便”
“你直接告诉我吧”
“我不知道不知道”
连续随机回答
长时间无输入
明显重复敷衍
```

AI Analyzer 输出：

```json
{
  "emotion_signal": "FRUSTRATED",
  "engagement": "LOW",
  "recommended_action": "DEESCALATE"
}
```

Tutor Engine 可执行：

```text
1. 停止继续追问原逻辑
2. 改成更简单生活场景
3. 允许语音讲解
4. 允许短休息
5. 必要时结束当前知识点
```

## 13.3 不允许的行为

- 连续 7、8 轮追问同一问题；
- “再想想”反复循环；
- 因孩子答不上而讽刺；
- 讲一大段后立即上高难题；
- 用奖励强迫继续。

# 15. Mastery 掌握状态

```text
UNKNOWN
EXPOSED
LEARNING
ASSISTED
UNDERSTOOD
MASTERED
REVIEW_DUE
REGRESSED
```

## UNDERSTOOD

至少满足：

- 不同表达形式；
- 非完全重复题；
- 至少一次独立完成。

## MASTERED

建议至少满足：

```text
生活情境独立完成
+
变式独立完成
+
课本形式验证
+
间隔复习成功
```

一次答对绝不能变成 MASTERED。

# 19. 语音教学

V1 支持两条路径。

## 19.1 STT 语音回答

孩子可按住或点击麦克风：

```text
录音
→ 上传服务端
→ STT
→ 显示识别文字
→ 孩子确认/提交
```

低年级和不愿打字时特别有价值。

## 19.2 TTS 讲解

触发：

```text
VOICE_EXPLAIN
```

场景：

- Socratic 三轮失败；
- 孩子主动点“给我讲讲”；
- 情绪降级；
- 需要语言/英语发音训练。

## 19.3 语音与文字同步

讲解响应包含语义片段：

```json
{
  "segments": [
    {
      "id": "seg_1",
      "text": "先看总价36元。",
      "audio_timing": {
        "start_ms": 0,
        "end_ms": 1820
      }
    }
  ]
}
```

前端播放时：

- 当前句高亮；
- 可暂停；
- 可重播当前句；
- 可切回文字；
- 不强制自动播放。

## 19.4 V1 动画原则

语音讲解时只做：

- 重点数字高亮；
- 箭头；
- 逐步出现；
- 当前文本行高亮。

不做复杂人物口型或 3D 老师。

# 28. Codex Content Pipeline 题库/内容流水线

Codex 负责题库资产，但不得让“生成即上线”。

## Stage 0 — Source Registry

记录：

```text
课程标准
学校/教材映射
公开授权资源
自研规则
事实来源
```

对于第三方网络题目：

```text
仅作为题型/难度研究；
不得默认复制为商业题库。
```

## Stage 1 — Outline Extraction

Codex 生成：

```text
KnowledgePoint
prerequisite
difficulty
misconception
scenario
assessment goal
```

## Stage 2 — Asset Generation

生成内部 JSON：

```json
{
  "question_id": "...",
  "knowledge_point_id": "...",
  "difficulty": "L2",
  "prompt_public": "...",
  "teacher_private": {
    "answer": "...",
    "solution": "...",
    "misconceptions": []
  },
  "life_connections": [],
  "source_provenance": {},
  "status": "DRAFT"
}
```

## Stage 3 — Deterministic Validation

Go/Python 工具：

- JSON Schema；
- 数值答案；
- 单位；
- 方程；
- 可枚举数学题；
- 重复检测；
- 选项唯一正确；
- 答案与解析一致；
- 图形数据基本约束。

失败：

```text
REJECTED_AUTOMATIC
```

## Stage 4 — Secondary AI Review

使用与 generator 不同的 prompt/角色，最好可使用不同模型。

检查：

```text
学科正确性
年龄适配
事实准确性
题意歧义
人文/历史事实
生活数据合理性
是否可能泄答案
是否有错误价值观暗示
```

输出：

```text
PASS
PASS_WITH_FIX
REJECT
NEEDS_HUMAN
```

## Stage 5 — Release Gate

只有：

```text
deterministic_validation = PASS
secondary_review = PASS
schema_version matched
```

才能：

```text
PUBLISHED
```

## Stage 6 — Runtime Feedback

若课堂发现：

- 多数孩子误解题意；
- 答案争议；
- AI多次异常；
- 家长报告错误；

自动：

```text
QUARANTINED
```

等待复核。

## 28.1 目标

不是宣称“零错误”，而是：

> 未验证内容不进入生产课堂；所有上线内容可追溯、可撤回、可重新发布。

# 45. OpenAI/Codex 当前能力约束

截至本规格编写时，OpenAI 已公开 Codex SDK，可将 Codex agent 嵌入应用/工作流，并提供结构化输出与上下文会话能力。因此在工程上可以实现 `TeachingAgentGateway -> CodexProvider`。

但产品层必须保持：

```text
Codex Developer
!=
Codex Tutor
```

孩子学习使用的 Tutor 必须运行在受限教学工具集之上。

语音层必须通过 provider adapter 封装，避免前端/业务逻辑绑定单一模型。

AI API 定价会变化，因此 `estimated_cost` 计算不能硬编码到业务代码；应使用版本化 price table：

```text
ai_price_catalog
provider
model
effective_from
input_price
cached_input_price
output_price
audio_price
```

每次调用记录所采用的 price catalog version。

# 46. 最终产品原则

V1 所有设计决策可以用以下问题检查：

> 这个功能是在帮助孩子自己形成理解，还是只是更快地把答案告诉孩子？

如果答案是后者，默认不做。

最终体验必须形成：

```text
世界提出问题
        ↓
孩子产生好奇
        ↓
AI不断追问
        ↓
孩子开始推理
        ↓
遇到困难
        ↓
系统识别根因
        ↓
换场景 / 补基础 / 语音讲解
        ↓
孩子自己重新解决
        ↓
抽象成课本知识
        ↓
隔几天重新验证
        ↓
孩子发现：
“原来这个知识真的能解释世界。”
```

这就是 AI Learning Tutor 与传统“老师讲、学生听、然后刷题”的根本区别。
