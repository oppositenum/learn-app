# 测试环境一键发布

这套流程用于把尚未合并的功能版本发布到测试服务器。日常使用不需要在
电脑上安装 Docker，也不需要接触服务器、镜像仓库或数据库密码。

## 发布前准备

从开发或审计回报中取得待测试版本的完整 40 位 commit SHA。例如 B2：

```text
0a789bb28c3913fa756a35a8b72f043202bc3618
```

只有已经完成代码审查、分支 CI 全绿的 SHA 才能发布。发布工作流还会针对
这个精确 SHA 重新运行全部 Go、真实 PostgreSQL 和 Web 门禁；测试失败时
不会接触服务器部署凭据，也不会修改测试服务器。

## 第一步：点击 Test Deploy

1. 打开 GitHub 仓库的 **Actions** 页面。
2. 在左侧选择 **Test Deploy**。
3. 点击右侧的 **Run workflow**。
4. `commit_sha` 粘贴完整 40 位 SHA。
5. `release_name` 填小写测试名称，例如 `b2-review-lifecycle`。
6. `confirmation` 填写大写的 `DEPLOY`。
7. 点击绿色 **Run workflow** 按钮。

工作流会依次完成：

```text
锁定精确 SHA
-> Go 静态检查和单元测试
-> 真实 PostgreSQL 集成测试（零失败、零跳过）
-> Web 测试、lint 和 build
-> 构建两个 linux/amd64 镜像
-> 验证镜像架构和 commit 标签
-> 服务器只读健康检查
-> PostgreSQL 备份并验证备份可读取
-> 切换测试 tag 并运行 migration
-> 验证 API、Web、PostgreSQL、HTTP 和 WebSocket 入口
```

全部变成绿色后，打开该次 run 的 **Summary**。确认其中显示：

- 正确的完整 commit SHA；
- API 和 Web 使用同一个测试 tag；
- 两个镜像都是 `linux/amd64`；
- 两个镜像各自的 `sha256` digest；
- 发布前 tag、当前测试 tag和数据库备份文件名；
- API、Web、PostgreSQL 都是 `healthy`。

任何步骤变红时不要重复点击发布，也不要自行修改服务器。保留该次 Actions
run 链接，让 Codex 检查失败点。发布失败后，服务器网关会在可能的情况下
自动恢复发布前镜像；数据库不会被自动删除或恢复。

## 第二步：实际测试学习软件

Actions 全绿只证明构建、迁移和基础运行正常，不能代替实际功能测试。打开
测试站点，使用已有测试账号检查本批涉及的角色和功能：

1. 登录后页面能够正常打开和切换。
2. 学生可以进入课堂、提交回答并继续学习。
3. 家长页面能打开；需要实时验证的批次应确认 WebSocket 已连接。
4. 本批新增或修复的具体功能按施工令文逐项操作。
5. 学生页面和网络响应中不得出现标准答案或其他私有答案字段。

记录发现的问题和对应页面。功能不符合预期时，不创建该功能分支的 PR。

## 第三步：点击 Test Rollback

无论功能测试通过还是失败，测试结束后都要恢复发布前版本：

1. 回到 GitHub 仓库的 **Actions** 页面。
2. 在左侧选择 **Test Rollback**。
3. 点击 **Run workflow**。
4. `confirmation` 填写大写的 `ROLLBACK`。
5. 点击绿色 **Run workflow** 按钮。

回滚全绿后，在 Summary 中确认：

- `RESTORED_TAG` 是发布前记录的 tag；
- API、Web、PostgreSQL 都是 `healthy`；
- `APP_HEALTH=ok`；
- `API_HEALTHZ={"status":"ok"}`；
- `SCHEMA_ROLLBACK=not_performed`。

最后一项是正常提示：仓库 migration 是 forward-only。Test Rollback 只恢复
应用镜像，不会破坏性地删除表、删除列或恢复数据库。每次 Test Deploy 都会
在 migration 前创建经过读取校验的数据库备份；只有数据库确实异常时，才由
管理员在隔离实例验证备份后决定是否恢复。

## 日常需要记住的三件事

```text
发布时粘贴审计通过的完整 SHA，并输入 DEPLOY。
Actions 全绿后仍要亲自操作学习软件。
测试结束后一定运行 Test Rollback，并输入 ROLLBACK。
```

不要把 GitHub Secret、SSH 私钥、镜像仓库凭据、测试账号密码或数据库备份
内容粘贴到对话、Issue、PR、Actions 输入或仓库文件中。
